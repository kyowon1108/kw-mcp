# 광운대 캠퍼스 도구 계획

기준일 2026-11-05. 이 문서가 현재 계획입니다. 다른 문서는 참고 자료입니다.
- `campus-roadmap.md`: 조사 보고서 (게시판 목록, 데이터 소스, 규정·법 검토)
- `aws-architecture.md`: 공개 영역 운영 설계 (학교 서버 예절, 보안, 운영 절차)
- `relay-design.md`: 암호화 캐시를 서버에 올리는 이전 설계. 위협 분석과 로그 규칙만 참고합니다.

## 1. 목표와 원칙

**목표**: Claude(데스크톱·웹·모바일)와 ChatGPT에서 내 KLAS 정보와 학교 공개 정보를 합쳐서 묻고 답을 받습니다. 학교 공지는 Discord로 알림을 받습니다.

**원칙**
- 서버에 KLAS 비밀번호, 학번, 개인 학사 데이터를 **저장하지 않습니다.** 서버에 남는 것은 무작위 ID와 해시뿐입니다.
- 각자 **자기 데이터만** 봅니다. 연결마다 무작위 ID가 붙고, 다른 사람 것을 조회하는 경로가 없습니다.
- 읽기 전용입니다. 제출, 출석, 수강 같은 쓰기 기능은 없습니다.
- 학교 서버에는 목록 페이지만, 서버(IP)마다 간격을 두고 요청합니다. 막히면 멈춥니다.
- 비밀번호를 어디까지 보낼지는 **사용자가 고릅니다** (아래 세 가지 연결 방법).

## 2. 연결 방법 세 가지

| 방법 | 사용자가 하는 일 (한 번) | 되는 곳 | KLAS에 로그인하는 곳 | 비밀번호 위치 | 조건 |
|---|---|---|---|---|---|
| **1. Claude 데스크톱 확장** (`.mcpb`) | 파일 더블클릭 → 학번·비밀번호·초대 코드 | Claude 데스크톱 | 내 PC | OS 키체인 | Claude 데스크톱 실행 중 |
| **2. PC 에이전트** | 설치 명령 한 줄 → 커넥터 추가 → 연결 코드 입력 | Claude 전부, ChatGPT | 내 PC | OS 키체인 | PC가 켜져 있음 (브라우저 불필요) |
| ~~간편 연결~~ (꺼 둠) | 커넥터 URL 추가 → 승인 페이지에 초대 코드·학번·비밀번호 | 어디서나 | AWS Lambda (서울) | 암호화해 연결 토큰 안에 | **KLAS가 AWS IP 로그인에 2차 인증을 요구해서 쓸 수 없음** |

- 세 방법 모두 KLAS 세션이 만료되면 **자동으로 다시 로그인**합니다. 사용자가 손댈 일은 비밀번호를 바꿨을 때뿐입니다.
- **간편 연결을 끈 이유** (2026-11-05 실제 시도): KLAS는 2026-10-26부터 해외로 보이는 IP의 로그인에 2차 인증(앱·이메일)을 요구하고(공지 DUID 53483), AWS 서울 Lambda의 IP도 그렇게 분류됩니다. 서버가 다시 로그인할 때마다 사람이 인증해야 하므로 "한 번 설정하면 끝"이 안 됩니다. 국내 IP 프록시로 피해 가는 것은 학교 보안 장치 우회라서 하지 않습니다. 코드는 SSM `/kw/bridge/password-mode`로 꺼 둔 채 남겨 두었습니다. 다시 켜려면 보안 검토 지적 사항(초대 코드별 학번 묶기와 일일 시도 제한, 인가 코드 URL에서 봉인 블롭 빼기)을 먼저 고쳐야 합니다.
- 브라우저 확장은 만들지 않습니다. 크롬이 켜져 있어야 하고, 위 세 방법이 더 쉽습니다.
- 안내 페이지: `https://<bridge>/setup#<초대코드>`에 세 방법이 쉬운 순서로 나옵니다.

## 4. 동작 흐름

**간편 연결** (꺼 둠, 참고용)
1. Claude·ChatGPT가 커넥터 URL을 받으면 OAuth로 우리 승인 페이지를 엽니다.
2. 초대 코드를 먼저 확인합니다. 그다음 서버가 KLAS에 한 번 로그인해 학번·비밀번호가 맞는지 봅니다.
3. 학번·비밀번호를 AES-256-GCM으로 봉인해(키는 SSM, 그 OAuth 클라이언트에 묶임) 인가 코드·갱신 토큰·액세스 토큰 안에 넣어 돌려줍니다. DB에는 토큰 해시만 남습니다.
4. 도구를 부르면 토큰을 메모리에서 풀어 KLAS에 로그인(또는 15분 안 쓴 세션 재사용)하고, 결과를 공개 정보와 합쳐 답합니다.

**PC 에이전트**
1. `kw-mcp link <초대코드>`: 학번·비밀번호를 키체인에 저장 → KLAS 로그인 확인 → 기기 키(P-256)를 만들어 공개키만 서버에 등록 → 로그인 시 자동 실행 등록 → 연결 코드(15분, 1회용) 출력.
2. 에이전트는 서버와 WebSocket을 계속 유지합니다(5분마다 핑, 끊기면 다시 접속).
3. 도구를 부르면 서버가 요청마다 새 AES 키를 만들어 에이전트에 보내고, 에이전트가 KLAS에서 읽어 그 키로 암호화해 올립니다. 서버는 메모리에서 풀어 답하고, 암호문은 바로 지웁니다(늦어도 2분).

**실패할 때**

| 상황 | 간편 연결 | PC 에이전트·`.mcpb` |
|---|---|---|
| KLAS 세션 만료 | 자동 재로그인 | 자동 재로그인 |
| 비밀번호 거부 | 그 연결을 즉시 멈춤(같은 비밀번호 재시도로 보안문자가 걸리는 것 방지). Claude·ChatGPT가 다시 연결하라고 띄움 | 10분 동안 재시도 안 함. `kw-mcp setup`으로 다시 저장 (에이전트는 재시작 없이 새 값 사용) |
| 보안문자·2차 인증·임시 비밀번호 | 멈추고 브라우저에서 직접 로그인하라고 안내 | 같음 |
| 연결 토큰 | 액세스 1시간, 갱신 토큰 180일 (쓸 때마다 새로 받음) | 같음 |
| PC 꺼짐·잠자기 | 상관없음 | "에이전트가 연결돼 있지 않습니다" |

## 5. 기능

**공개 도구**: 최신 공지·검색·공지 상세, 학식, 학사일정

**개인 도구**: 내 과목·시간표, 과제, 온라인강의, 퀴즈, 팀플, 과목 게시판 글, 마감 목록, 과제 상세(본문·제출 형식·첨부 이름·내 제출), 강의계획서, 게시판 글 본문

상세 도구는 PC 에이전트에 "call" 요청(허용된 읽기 작업만)으로 하나씩 읽어 옵니다. 에이전트는 접속할 때 프로토콜 버전을 알리고, 옛 버전이면 서버가 설치 명령을 다시 실행하라고 안내합니다(다시 실행해도 기기 등록과 커넥터 연결은 유지).

**합친 도구**

| 도구 | 합치는 것 |
|---|---|
| `this_week` | 과제·강의·퀴즈·팀플 마감(제출한 것 제외) + 같은 기간 학사일정 |
| `today_briefing` | 오늘 수업·강의실 + 오늘·내일 마감 + 오늘 학식 + 최근 과목 게시판 글·학교 공지 |
| `my_notices` | 최근 N일 내 과목 게시판 글 + 학교 학사·장학 공지 |

**알림**: Discord 채널은 공개 공지만.

## 7. AWS 구성 (서울)

- **공개**: 수집 Lambda(평일 20분마다) → `kw-public` → Streams → 분배 Lambda → SQS → Discord 전송 Lambda. 학식·학사일정 Lambda(평일 07:30). 공개 MCP(HTTP API, 초당 2건).
- **연결(bridge)**: HTTP API `kw-bridge` → Lambda `kw-bridge`(OAuth, 개인 MCP, 설치 파일, 공개 JSON API). WebSocket API `kw-bridge-ws` → Lambda `kw-bridgews`. 테이블 `kw-bridge`. 초당 5건 제한.
- **비밀값 (SSM)**: `/kw/bridge/jwt-secret`(토큰 서명), `/kw/bridge/seal-key`(간편 연결 봉인), `/kw/mcp/tokens`(초대 토큰 해시), Discord 봇 토큰.
- **공통**: CDK(Python). 함수마다 권한을 나눔(수집 함수는 연결 테이블·Discord 토큰 못 읽음 등). 로그에 토큰·개인 데이터를 남기지 않음. 오류 알람은 SNS.

## 9. 남은 확인

- API 전체 초당 5건 제한이 IP별이 아니라서, 누가 계속 두드리면 모두 429를 받음 (HTTP API에는 WAF를 못 붙임)
- Claude 데스크톱 설치 창(설정값 입력)을 거친 `.mcpb` 설치: 친구 첫 사용 때 확인
- Windows 실제 PC에서 KLAS 로그인까지 (설치·자동 실행·잠금은 GitHub Actions Windows 러너에서 운영 서버 설치 스크립트로 확인, `.github/workflows/windows-agent.yml`)
- KLAS가 AWS IP 로그인을 막거나 이상 로그인으로 보는지 관찰
- 알람 메일 구독, root 대신 배포용 IAM 역할
